Capabilities

The hard parts of running WordPress, already solved.

Most "managed WordPress" hosts hand you a faster shared box and a caching plugin. We hand you a real Kubernetes platform — page caching, scaling, DNS, secrets, and rollouts engineered at the infra layer, not bolted on with a plugin.

Page cache that never touches PHP

Nginx + srcache + Lua serve hot pages straight from Memcached or Redis in single-digit milliseconds. Cache misses spawn a single backend request and refill the cache atomically. No WP plugin, no wp-content/cache, no nightly cache purges that nuke your site.

Four PHP versions, one runtime

PHP 8.1, 8.2, 8.3, 8.4 — purpose-built runtime images for each. Pin per site. Upgrade one site without touching the rest of the fleet. Canary the new minor on staging, then promote the same image tag to prod.

Cluster-native DNS, the way it should be

Configurable nginx resolver. Point it at your cluster DNS (10.96.0.10), and every proxy_pass resolves cleanly to internal services. No more hardcoded 8.8.8.8 like the upstream stacks still ship with.

GitOps-native, top to bottom

A site is a Kubernetes Wordpress CR. Commit it. Let Argo CD or Flux apply it. The operator reconciles Deployments, Services, Secrets, and PVCs to match. No dashboards. No drift. No "who deployed what at 4pm Friday".

Bedrock-style site template, batteries included

Composer-managed plugins. Environment-driven config. Secrets via Kubernetes, not wp-config.php. New sites boot locally in one command and ship through the same operator that runs production. Clone the template, edit one file, push.

Gateway API + your edge of choice

Routing is decoupled by design. Point an HTTPRoute, an Ingress, a Cloud Load Balancer, or your existing CDN at the Service the operator generates. Your platform team keeps owning the edge — we don't try to take it.

Why it's faster

Faster than "managed WordPress" because it isn't.

Most hosts measure WordPress performance from inside PHP. We refuse to enter PHP at all unless we have to. That's where the speed comes from — not a marketing slide.

01

The cache is in nginx, not in WordPress.

Plugins like WP Rocket cache after WordPress has already loaded — every request still spins up PHP-FPM, parses 50+ plugins, and connects to MySQL. We cache before WordPress. Hot pages skip PHP entirely. Cold pages refill the cache in one trip.

02

Replicas scale horizontally, like real software.

Traffic spike? Bump spec.replicas, or let the HPA do it for you. The operator rolls new pods, the Service fronts them, the cache stays warm across replicas because it's external. No "upgrade your VM" downtime. No five-minute IIS reboots.

03

Config is generated at startup, from your environment.

Dockerize templates render nginx + PHP-FPM config at container boot from spec.env. Want a different cache backend? One env var. Different upload limit? One env var. No SSH, no nginx -s reload, no config drift between staging and prod.

04

It's open source, so you can prove every claim on this page.

Three repos. wordpress-operator & wordpress-runtime are Apache 2.0; wordpress-site-template is MIT. Read the controller code. Read the nginx templates. Run it on your own cluster and pay us nothing. We're confident enough to compete on operations, not lock-in.

Frequently asked

Answers to the questions enterprise buyers actually ask.

Where does my site actually run?

On a managed Kubernetes cluster — ours, or one in your own cloud account. Either way you get the same operator, the same runtime images, and the same upgrade path. No proprietary control plane, no escape hatch you can't open.

Can we keep our existing themes and plugins?

Yes. We ship a Bedrock-style site template that uses Composer for plugin management, but you can run any standard WordPress codebase. Custom plugins, premium themes, mu-plugins, drop-ins — all supported.

How do migrations work?

We import your existing site (database + uploads + codebase) into a staging environment running on our stack, run the diff against your live site, and cut over with DNS. Most migrations finish in a single business week.

What's the SLA?

99.95% on Growth, 99.99% on Enterprise, both measured at the application layer (TTFB on a cached request) — not just at the load balancer. Credits are automatic and posted on the next invoice.

If it's open source, why pay you?

Because running stateful workloads on Kubernetes on call at 2am is its own job. You're paying for the operations, the SLA, the response time, and the years of WordPress edge cases we've already handled. The code stays free either way.

Do you offer SSO, audit logs, and data residency?

On the Enterprise tier, yes — SAML / OIDC SSO, immutable audit logs, and region-pinned data residency including EU-only options for GDPR-sensitive customers.
